# Contributing / コントリビューション

[English](#english) | [日本語](#日本語)

## English

Bug fixes, tests, documentation, accessibility improvements, and focused examples of Laravel testing patterns are welcome.

1. Search existing issues first. Discuss substantial behavior changes in an issue before implementation.
2. Create a focused branch from `main`.
3. Add or update tests when behavior changes.
4. Run `composer check`.
5. Update both READMEs when user-facing behavior changes.
6. Open a pull request describing the reason, implementation, and verification.

Never include production credentials, personal data, or a real application database. Contributions are licensed under the MIT License.

## 日本語

不具合修正、テスト、文書、アクセシビリティ、Laravelのテスト手法を示す目的の絞られた改善を歓迎します。

1. 既存Issueを検索し、大きな仕様変更は実装前にIssueで相談します。
2. `main` から目的を絞ったブランチを作ります。
3. 動作を変える場合はテストを追加・更新します。
4. `composer check` を実行します。
5. 利用者向けの変更では両方のREADMEを更新します。
6. 理由、実装、確認方法を説明したPull Requestを作成します。

本番の認証情報、個人情報、実運用のデータベースを含めないでください。コントリビューションはMITライセンスで提供されます。
